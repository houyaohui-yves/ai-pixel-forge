# 图片换脸工作区架构

这个工作区提供本地浏览器界面，围绕人脸素材整理和单张图片换脸建立可复用的处理能力。浏览器、HTTP、文件存储与单帧处理分层，后续视频工具可以直接复用 `FacePipeline`，无需调用网页接口，也无需把视频帧写成临时图片。

## 模块与职责

| 模块 | 当前职责 |
| --- | --- |
| `web/` | 图片导入、人脸选择、模型选择、融合参数、结果预览与下载、人物素材库操作。 |
| `facework/server.py` | 仅监听本机的 HTTP 适配层；校验请求、串行调度推理、组织响应与本地文件访问。 |
| `facework/storage.py` | 解码图片、按 EXIF 校正方向、本地记录、人物素材管理、质量报告、带 DFLJPG 元数据的对齐人脸导出。 |
| `facework/pipeline.py` | 与 HTTP 和文件路径无关的单帧编排：检测、选脸、对齐、预测、融合；缓存检测器和当前人物模型。 |
| `facework/detection.py` | 用 PyTorch 复现 DFL 的 S3FD 人脸检测和 2DFAN 68 点定位，复用对应权重。 |
| `facework/geometry.py` | DFL 约定的人脸对齐、素材质量启发式检查、颜色匹配、遮罩处理和回贴。 |
| `facework/model.py` | 当前支持的 SAEHD 推理结构、模型配置读取和输出遮罩组合。 |
| `facework/weights.py` | 受限读取 DFL 的 NumPy pickle 权重，转换并缓存 PyTorch 张量；缺失权重明确报错。 |

这不是对 DFL 启动脚本的封装：检测器和 SAEHD 推理在本项目内使用 PyTorch 执行，对齐和融合逻辑也不依赖 DFL 的命令行或 TensorFlow 运行时。相关改编代码保留 DFL 的 GPLv3 归属；完整许可证与来源见工作区中的许可文件。

## 单帧接口与颜色约定

```python
faces = pipeline.detect(frame_bgr)
result = pipeline.process_frame(
    frame_bgr,
    model_descriptor,
    face=faces[selected_index],
    options=BlendOptions(feather=8, erode=4, color_match=True),
)
# result.image: uint8 BGR，尺寸与输入相同
# result.mask: uint8 单通道、原图大小的实际融合遮罩
```

`process_frame` 也可用 `face_index` 让内部检测器选脸。传入 `face` 时，调用方负责提供与该帧匹配的框和 68 个关键点；视频跟踪器未来可使用这个入口。函数不会处理音轨、帧率、人物跟踪或跨帧平滑，也不自动为后续帧保留人物身份。

内部图像约定统一为 `uint8 BGR`：导入时由 Pillow RGB 转换为 BGR；S3FD/FAN 在其网络入口转回 RGB；SAEHD 接收归一化 BGR；预测结果继续按 BGR 融合并使用 OpenCV 编码。混合模型输出的源脸与目标脸遮罩后，在对齐空间收缩、羽化，再反向变换至原图。颜色匹配只使用有效遮罩与原图覆盖区域；预乘透明度回贴用于避免黑色裁剪边缘渗入。输出遮罩为零的像素保持原图字节不变。

## 人物素材与人物模型

人物素材库和已训练模型是两类资产，不能互相代替。

- **人物素材库**保存所选朋友的照片、对齐人脸、源图关系和人工筛选所需的质量提示。添加照片不会自动训练模型。
- **人物模型**是已经学习过源人物和目标人脸数据的 SAEHD 参数。换脸页面选择模型决定生成哪位人物，选择目标图片中的脸决定替换位置。
- 质量报告中的清晰度、亮度和左右偏转值是辅助整理的启发式指标。左右偏转不是角度，检测置信度也不是身份相似度或最终画质分数。
- 当前素材导出包含 `aligned/`、`sources/` 和清单。对齐 JPEG 写入 DFLJPG APP15 元数据，保留关键点、原图名称、原图人脸框和变换矩阵，便于后续训练流程使用。

高质量训练素材仍需要人工检查身份是否一致、关键点是否正确，以及角度、表情、光照是否覆盖目标用途。重复检测只能减少完全相同的对齐图片，不能替代近重复筛选或身份核验。

## 当前支持边界

- 支持已训练 **SAEHD `df` / `df-d`** 推理；不支持 `liae`、`df-ud`、AMP、Quick96 或其他网络结构。
- 人脸类型支持 `h`、`mf`、`f`、`wf`，不支持 `head`。模型分辨率必须与权重配置一致。
- 检测最多返回八张脸；一次图片处理替换用户选中的一张脸。
- 不包含训练器、XSeg 遮挡分割、FAN 二次检测/多采样平均、脸部超分、视频编解码、跟踪或时间平滑。
- 不通过“补齐随机参数”掩盖损坏或缺失权重。架构名称被支持也不等于所有来源的检查点已经完成兼容性验证。

当前已经在 Mac 的 CPU 路径上用原项目文档样例执行真实 S3FD/FAN 检测，并目视核对关键点。移植按照上游网络和坐标约定编写，但尚未完成 TensorFlow 与 PyTorch 的逐层数值一致性验证；不能将“运行成功”表述为“与原版结果逐像素一致”。

设备选择会检查 CUDA 和 MPS 是否可用，并提供 CPU 路径。本机 Mac 已完成 CPU 与 MPS 的真实模型推理、HTTP 流程和浏览器操作验证，详见 `validation.md`。Windows CPU / CUDA 尚未实机验收；单个样例的运行结果不能替代其他模型和平台的兼容性验证。

## 视频复用边界

视频抽帧、逐帧换脸、重新合成描述了基本的数据流程，但优质视频还需要独立处理：

1. **人物跟踪与重识别**：让同一模型持续替换同一人物；不能每帧简单选择面积最大的脸。
2. **遮挡与失检策略**：处理手、头发、物品遮挡及出画；明确何时保留原帧。
3. **时序一致性**：对框、关键点、遮罩、颜色进行合适的稳定处理，降低抖动和闪烁。
4. **时间与媒体信息**：保留帧时间戳、处理可变帧率、旋转方向、音轨和音画同步。
5. **任务控制**：顺序处理、进度、取消、恢复和有限内存队列。

未来视频模块应负责以上状态与编解码，将选中的当前帧人脸传给 `process_frame`，复用本项目的检测、几何、人物模型和融合能力。图片工作区继续保留独立入口；视频相关状态不混入浏览器或单帧推理模块。
